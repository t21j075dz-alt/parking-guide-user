### 駐車位置をアプリの再読み込み後も保持（2026-10-30）

- YOLOで案内枠に車を検知し、利用者が「はい、自分の車です」と回答したとき、現在の施設ID、区画UID、番号、小規模な公開配置図を**この端末のlocalStorage**へ保存する。車両の画像・ナンバーや正確な位置情報は保存しない。
- iPhoneがメモリ不足やOSのバックグラウンド制限でページを再読み込みしても、記録があれば駐車中画面を復元し、区画番号とマップを再表示する。配置図が再取得できなくても保存時点の図を利用する。
- 駐車中画面の間はアプリ上部のホームロゴやブラウザーの戻る操作では今回の記録を破棄しない。**「出庫してホームへ戻る」を押すとlocalStorageから記録を消去して施設選択に戻る。**
- ブラウザーのデータ削除、プライベートブラウズ、保存容量制限、端末の変更では保持できない。駐車位置をSupabaseの個人アカウントへ送信・同期しない。
- 回帰テストは端末内保存 → アプリの別起動 → 駐車位置とマップの復元 → 出庫時削除、および破損データからの安全な初期表示を確認する。

## 駐車中の車両検知と本人確認・駐車位置の保存画面（2026-10-30）

案内している区画の最新のYOLO判定が、新しく「occupied（使用中）」へ変わり、別々の時刻で2回以上・2秒以上継続した場合だけ、利用者画面に「駐車したのはご自身の車ですか？」と表示します。**YOLOは車の所有者を特定しません。利用者本人が安全な状態で確認することが必須です。**

- **はい、自分の車です**：案内と位置監視を終了し、「駐車中」画面へ移行します。**駐車区画番号・施設名・利用者の区画マップ**を残し、使用中の自分の区画を目立つ枠で示します。カメラのライブ更新は停止し、録画用の映像と混同しません。
- **いいえ、別の車です（再探索）**：最新の区画情報で再検索し、直前に別の車が入った区画は新しい結果候補から除外します。他の空き区画が見つからなければ「空きなし・再探索」を表示します。
- **出庫してホームへ戻る**：本人が出庫時に押した場合だけ、今回の駐車番号とマップを破棄して施設選択へ戻ります。研究用の駐車位置は今回の端末セッション内だけ保持し、利用者の車両情報をSupabaseには保存しません。
- 安全対策：録画実演・音声テスト・非公開データ・古い20秒以上のカメラ判定・同じ映像フレームの繰り返しでは本人確認を開始しません。既存の運転者操作制限も適用します。
- 研究用音声台本の「arrival_detected」は「ご自身の車ですか？」という質問に変更しました。新しい固定文3部品をSupabaseの生成待ちへ登録済みです。完成までは端末音声で補います。
- GitHub Actionsの回帰テストでは、2回の新しいYOLO検知と古いカメラ判定の除外、本人による駐車完了、番号とマップの保持、出庫時の復帰、別車両時の除外付き再探索を確認します。実際のカメラとiPhoneを使用した最終動作確認は未実施です。

### 保存済み音声1,000件制限の解消（2026-10-30）

- Supabaseの公開音声一覧を `/rest/v1/parking_voice_ready?select=audio_hash&limit=1000` から、`/rest/v1/rpc/parking_voice_ready_hashes` へ変更。
- RPCは `SECURITY INVOKER` で動作し、`parking_voice_ready` に公開済みのSHA-256識別子のみを返す。施設名などの非公開ジョブ本文にはアクセスしない。
- 1,000件を超えた施設・店舗・区画番号の音声も、完成済みであれば一覧に含まれるようにする。1.4秒タイムアウトと15秒再試行抑制は引き続き適用し、ネットワークが弱いときは端末の読み上げへ移行する。
- Supabase Storageの現在のMP3は323件すべて存在し、MIMEタイプ `audio/mpeg`、最小サイズ10,125バイト、生成完了フラグと公開一覧の照合も一致している（2026-10-30確認）。
- 1,000件以上の一覧を返す状態の自動テストを追加。将来、数万件規模の音声でレスポンスが1.4秒を超える場合には、施設別の音声取得などに改良する必要がある。

### 弱い回線でも音声が止まらないための通信制限（2026-10-30）

- 施設・店舗・駐車枠の完成済み音声をSupabaseから取得する前に、音声一覧（`parking_voice_ready`）を参照する。この通信はヘッダー取得だけでなくレスポンス本文も含め、最大1.4秒で終了する。
- タイムアウト・通信エラー・一覧取得失敗の場合は、生成済み一覧の再取得を15秒控える。複数の固定文が同時に要求されても同じ通信失敗を繰り返さない。
- 一覧が取得できない場合、存在するか不明な音声ファイルを無差別に取得しない。未生成の音声と同じくWeb Speech APIへ切り替える。
- 以前取得した生成済み一覧がある場合はその情報を使用でき、端末キャッシュに保存済みの音声は一覧通信すら不要。施設名・店舗名・番号を読み上げる組み立て方式は維持する。
- 端末音声の動作はブラウザーとOSに依存するため、iPhoneや車載Bluetooth・CarPlayの実機動作を保証しない。

### 音声部品の読みに不一致がないか照合・再生開始の高速化（2026-10-30）

- 台本の固定文86種類と、Supabaseの生成済み・生成待ち音声の本文を突き合わせると、「空き区画は模擬データです。」の読みだけが一致しなかった。アプリが使う `あきくかくは模擬データです。` を新たな共有音声部品として生成待ちに登録。
- 日本語音声の自動置換が「お客様の駐車場所は、」を「お客様のちゅうしゃじょう所は、」に破壊していたため、より長い「駐車場所」を優先して `ちゅうしゃばしょ` と読むよう修正。訂正版も音声生成待ちへ登録。
- 音声部品を順番に1個ずつデコードすると、20件以上の部品がある案内で長い待ち時間になりやすいため、最大6件ずつ並列デコードへ変更する。番号を2回発話する順序はそのまま維持。
- 初回のMP3生成・保存にかかる時間は外部音声サービスの制限に依存する。新しく登録した2部品が生成完了するまでは端末音声へフォールバックする。

### 選択した施設の駐車枠番号・到着案内を先読み（2026-10-30）

- 利用者が施設を選択すると、保存済みの「案内開始」音声と、レイアウトに登録された実際の区画番号（日本語読み、最大48種類）を先に取得する。次いで「目的地への接近」「再探索」「空き枠がない場合」「空き枠が見つかった場合」「安全上の注意」の固定音声を準備する。
- 区画番号は `getSpokenSpaceId` を使用し、表示と読み上げの列名、エリア名、ゼロを除いた番号を一致させる。選択した施設に区画マップがない場合も案内音声の先読みは継続する。
- 保存済み音声のローカルキャッシュを利用し、必要な場合だけSupabaseの準備完了ファイルを3部品ずつ取得する。生成待ちの音声を新規合成せず、未生成部品が残る場合は端末音声を使用する。施設を変えた場合は古い先読みを停止する。
- データ通信を圧迫しないため大規模レイアウトは先頭48種類に限定する。全ファイルの即時取得・全件オフライン再生を保証するものではない。

### 施設選択時の案内音声部品先読み（2026-10-30）

施設を選択すると、音声の再生に必要な施設名に加えて、開始・接近・再探索の共通音声を最大3件ずつ先読みする。選択店舗を変更した際も同様に新しい店舗名の保存済み音声を先読みする。先読みは完成済み音声の取得のみで、外部tts.questへ新規合成要求を送らない。選択変更で古い先読みループは停止する。保存されていない部品は従来どおりブラウザー音声で発話する。利用者側の制限されたネットワークに過度に負荷をかけない。

### 生成済み音声ファイルを既定で優先（2026-10-30）

新規利用者では保存済み音声の組み立て再生を最初から有効にする。利用者が明示的にOFFにした場合は次回もOFFを維持。案内中の未保存音声は端末で読み上げ、外部tts.questへ自動生成要求を送らない。店舗を選択した時点で完成済み音声のみ先読みする。

### 音声生成済み一覧・案内の区切り改善（2026-10-30）

- Supabase `parking_voice_ready` は生成済み音声のSHA-256識別子のみを公開する。店舗名の本文や生成待ちの内容は公開しない。RLSで公開読み取りのみ許可する。
- アプリは一覧を最大2分キャッシュし、存在しない音声ファイルへの404問い合わせを省略。準備済みの店舗名・施設名・固定文を共通Storageから取得し、端末にも保存する。
- 音声は「まもなく目的地」「案内する駐車枠」「繰り返します」「同じ駐車枠」「安全に関する案内」の位置で文を分け、間を置く。店舗名は分割せず一つのまとまりとして読む。
- サーバー側の音声生成は30秒ごとに最大1件へ変更し、HTTP 429の際は既存の30分クールダウンを継続する。完了する件数は外部音声サービスの制限に依存する。

### Supabaseで施設・店舗名を事前生成・共有（2026-10-30）

管理者アプリで施設内店舗を新しく追加するか改名し、Supabaseへのレイアウト保存が成功すると、音声サーバーの生成待ち行列へ名前を自動登録します。管理者ログイン時には既存施設・店舗名の一覧も同期します。

- Edge Function `parking-voice-prepare` は管理者本人を `parking_camera_operators` で照合し、一般利用者からの生成登録を拒否します。
- Supabase Storageの公開バケット `parking-voice` に `ja-JP/<hash>.mp3` として生成音声を保存します（入力された施設名・店舗名を公開URLに表示しません）。
- 利用者アプリは保存済みの施設・店舗名音声を、既存の端末キャッシュより後、通常の端末音声へ戻す前に取得します。クラウド音声取得は該当する名前部品に限定し、未生成のままでも案内を止めません。
- 固定文とエリア名・番号などの案内は従来の部品再生と端末音声フォールバックを維持します。区画番号は同じ場所を2回案内します。
- 文ごとに区切り、特に「まもなく目的地」「区画番号」「繰り返します」の直後は長めの間を設けます。
- 既存施設212件の名称と固定文84件を生成待ちに登録しました。完成件数は管理者アプリの「音声の準備状況を更新」で確認してください。外部音声サービスのHTTP 429発生時は30分間生成を延期し、保存済みの音声だけを提供します。生成待ちと音声ファイル生成完了は区別してください。

### 音声台本とアプリ表示の統一・外部エラーに依存しない組み立て再生（2026-10-30）

- 駐車枠の音声は「固定文＋選択施設／店舗名＋1区画番号（2回）」を組み立てる仕様。保存済み部品が揃えば、キャッシュ済みの音声をWeb Audioで順番に再生する。
- **一部でも保存されていない場合は端末の音声で、同じ部品から組み立てた自然な文単位を順番に再生する。** 事前生成は必須ではなく、外部サービスのHTTP 429でも案内を継続できる。
- 再生時のtts.questへの自動生成要求は行わない。外部サービスへの送信は、停車中に利用者が任意の「事前保存」を押した場合だけ。失敗は一時的な問題として表示し、通常の未保存状態を赤いエラーにしない。
- 待機画面・検索結果画面に**実際に読み上げる内容**と再生状態を表示。運転中の操作を避けるため、聞き直しボタンには安全確認を適用する。
- 結果画面の操作名を「再探索」「案内をもう一度聞く」「駐車完了」に合わせる。対応していない入口通過や退出判定の音声は自動再生しない。
- 音声出力はiOSやブラウザーの実装に依存するため、自動再生とCarPlayでの完全動作は実機試験が必要。案内内容は文字でも確認可能にする。

### 外部音声HTTP 429の回避と多言語端末音声の改善（2026-10-30）

- tts.quest がHTTP 429を返した場合、以後30分は新しい生成を要求せず、保存済み音声・端末音声で案内する。待機期間を端末で保持する。
- **走行中は未保存の文章を外部TTSで生成しない**。保存済み音声部品・保存済み全文があれば使用し、無い場合は端末音声へ即時切替する。
- 施設・店舗名の一括生成は毎回新規8件まで。すでに保存したものは再生成せず、残りは手動で次の8件を作成。429中はボタンを押しても生成しない。
- 日本語以外（英語・中国語・韓国語・スペイン語）は端末の実在音声から選択し、同一地域の音声と高品質・端末内音声を優先しつつ、Google音声も候補とする。端末にGoogle音声が存在しない場合に「Google音声」を装っていない。
- Google Cloud Text-to-Speechそのものの有料APIは組み込んでいない。Google Cloud側の課金設定と資格情報が未提供のため、現段階では無料の端末側高品質音声を優先する。
- 端末側の音声はWeb Speech APIのブラウザー実装に依存し、特にiOSでアプリ背景化・画面ロック時の再生を保証しない。

## 2026-10-29 既存の施設・区画案内 → カメラ駐車確認（自宅研究用）

新しい「行きたい区画を登録」操作は設けていません。従来どおり施設と条件を選び、「今すぐ空き区画を確認」または250m接近時の自動検索を利用します。検索結果で**既存の案内処理が選んだ区画（`recommendedSpace.uid`）**をカメラの駐車確認対象にします。

1. ノートPCで`ホーム駐車場_ライブ共有.cmd`を起動し、撮影映像からSupabaseへ区画状態を送る。
2. 管理アプリで「自宅テスト用」を開き、管理者ログイン後「カメラによる空き状況・車両追跡」を開く。利用者アプリにリアルタイムデータを表示する際は、必要性と公開範囲を確認して「利用者アプリへ最新の空き状況を公開」をONにする。
3. 利用者アプリでは今までと同じ施設選択→条件選択→空き区画検索を使う。**カメラで空きを確認できた区画のみ**案内先が決まる（初期未確認区画は勝手に空きにしない）。
4. 自宅で実際のカメラ連携中、案内先画面に「カメラによる駐車確認」が追加表示される。**別の希望区画を登録するボタン・選択欄はない**。
5. カメラ判定の`occupied`が案内開始後に当該区画で新しく観測され、3秒間隔の取得で連続検証できた場合、「自分の車の駐車を確認して案内終了」が有効になる。移動中の操作は禁止。
6. 停車後に利用者本人が確認して案内を終了する。YOLOは車の占有を判定するが、車の持ち主を識別できない。管理アプリには、カメラで駐車を検知した区画が表示される。

**制限:** 利用者アプリの案内完了操作と、その利用者個人の希望を管理アプリ側の独立したセッションとして同期する機能は未実装。管理アプリで分かるのはカメラによる「区画の駐車中」までであり、ユーザーごとの「案内終了」を確認したものではない。双方の真正なセッション連携には認証・プライバシー保護された共有セッションが別途必要。

公開設定は検証後にOFFにする。通信中断や20秒以上古い区画状態は`unknown`となり、空きとして案内しない。

- 追加した「駐車場案内」のアイコンから起動すると、対応端末ではブラウザーの通常のツールバーを出さずに表示します。
- オフライン保存の完了は、ページの「ホーム画面に追加して使う」を開くと確認できます。端末やブラウザーが保存データを消した場合は、再度オンラインで開く必要があります。
- 通信できないときはオフライン表示を出し、基本画面・同梱データ・研究用シミュレーションを利用できます。最新の管理データ取得と外部音声の生成には通信が必要です。取得済みの管理データは現在開いている画面のメモリー内だけで保持し、PWAのキャッシュには保存しません。
- 更新がある場合は画面に通知します。停車中に「更新して再読み込み」を押すと、その画面を更新します。すべてのアプリ画面を閉じてから開き直しても更新されます。更新ボタンの再読み込みでは、その時点の案内が終了するので、施設・条件を選び直してください。
- Safariで保存した設定や自宅テスト地点が、ホーム画面版でも共有されるとは限りません。追加後のアプリ内で設定と位置情報の許可を確認してください。
- PWA化だけでは利用者を研究室に限定できません。現在のGitHub Pagesとリポジトリは公開されています。研究室だけにアクセスを限定するには、別途認証付きの配信環境が必要です。
- PWA化しても、画面ロック・バックグラウンド中の位置情報更新やCarPlay連携は保証しません。

### PWAのファイルと更新方法

`manifest.webmanifest` がアプリ名・起動URL・アイコンを定義し、`pwa.js` が追加案内・通信状態・更新操作を担当します。`service-worker.js` は、このアプリのパスにある指定済みの静的ファイルだけをまとめて保存します。Supabase、Google Maps、外部音声、未登録URL、POST通信はキャッシュしません。

配信するHTML・CSS・JavaScript・アイコン・同梱データを変更したら、**`service-worker.js` の `VERSION` を必ず変更**してください。HTMLのファイル名やクエリーを変更する場合は `SHELL_FILES` も合わせます。サービスワーカー本体は `updateViaCache: "none"` で更新確認します。

確認コマンド：`node --test tests/*.test.cjs`

## 位置情報と安全確認

位置情報は現在地から施設までの参考直線距離と、操作時の移動判定に使用します。

- 測位はメモリー内で使用
- 位置情報そのものは保存しない
- 移動を検知すると「運転中ですか？」を表示
- 「運転者ではありません」を選んだ後は、時間経過・停止と再移動・測位エラー・画面復帰・GPSの再開始でも確認とOS通知を出さない

- GPSだけでは運転者と同乗者を区別できないため利用者確認を併用

位置情報を利用する場合はHTTPSまたはlocalhostで開いてください。

## Bluetooth・CarPlay接続時の音声案内

- Safariの初期設定は `playback`（メディア再生）、その他は `play-and-record`（通話向け）。Safariで聞こえないという実機報告を受けて代替設定を追加した。これは出力先や実音量を保証するものではない（対応ブラウザーのみ）。マイクの起動や実際の通話は行わない。
- 自動案内開始時、空き区画を決めたとき、手動で再案内するとき、試聴するときは同じ読み上げ経路を使用する。
- 従来の「音楽と同時」「案内を優先」「端末の標準設定」も残し、切り替えた設定は端末内に保存する。
- 旧版の通話向け既定値はSafariではメディア再生へ移行する。V3で明示した設定は保持する。音楽と同時・案内優先・端末標準も選べる。
- メディア再生、案内優先、通話向けは他アプリの音楽を停止する場合がある。案内終了後は `ambient` へ戻すが、他アプリの自動再開を保証しない。
- CarPlayやBluetooth側の実際の出力先・音量、画面ロック中の継続読み上げはブラウザーから保証できない。車載機で必ず試聴する。

## 無料の多言語音声案内

利用者画面の音声案内は、外部AI APIではなくブラウザー標準の **Web Speech API（SpeechSynthesis）** を使用します。

- APIキー不要・従量課金なし
- 日本語表示時は **Google 日本語** を固定で優先
- 日本語の読み上げ速度は **1倍（標準速度）**
- English表示時は以下の音声案内言語を選択可能
  - English (US)
  - English (UK)
  - 中文
  - 한국어
  - Español
- 選択肢上には音声エンジン名を表示しない
- 各言語で実在する高品質音声が一覧にあれば優先し、それ以外はGoogle音声を優先する。音量の大小は音声名から推定しない
- 端末にある音声を直接選び、速度0.8〜1.1倍、アプリ内音量10〜100%を言語ごとに保存できる
- 外国語の初期速度は0.9倍。端末音声の音量上限は1（100%）で、Web AudioのGainNodeによる増幅はできない
- 中国語は zh-CN、韓国語は ko-KR、スペイン語は es-ES
- 選択した言語に合わせて試聴・自動案内開始・駐車区画案内の文章も切り替える
- 言語を選択すると、その言語の短い試聴を自動再生
- Chromeの音声一覧が遅れて読み込まれる場合を考慮し、最大15秒待って対応音声を取得
- 選択言語の音声が端末に存在しない場合は画面上で明示
- 端末音声の経路ではアプリから外部TTSへ文章を送信しない。ブラウザーの音声が内部でオンライン処理するかは端末実装による。任意のVOICEVOX方式は下記を参照

### 通話向け経路へ音声ファイルを載せる任意の実験機能

使用音源は **VOICEVOX:春日部つむぎ**（声のスタイルID: 8）。
これは第三者提供のサービスであり、ネットワーク・CORS・生成待ち時間・利用制限で動かない場合は既存音声へ戻ります。

位置情報の緯度経度は送信しませんが、案内文に含まれる施設・店舗名、区画番号は送信されます。
運転中の試験操作を避け、車載機で静止状態のテストを実施してください。

### 台本33種類＋補助3種類の組み立て音声（2026-10-29）

添付台本を `voice-guide-scripts.js` に固定文・差し替え項目別の33案内パターンとして登録し、営業時間未登録・研究用録画注意・閉店前通知の補助3パターンを加えています（計36種類）。
日本語VOICEVOX音声では、登録済みの固定文、施設名、複合施設内の店舗名、駐車枠番号を**別々にキャッシュ**し、
使用時に AudioBufferSourceNode を時間順に並べて再生します。駐車枠は**1つの枠を2回**読み上げます。
施設が変わっても共通の固定文は再利用でき、名前や番号だけを新しく保存できます。

- 音声設定の「選択施設の案内文・駐車枠を事前保存」で、台本の固定文全体と選択施設の名前・登録駐車枠番号を準備します。
- 「全施設・店舗名を事前保存」は、実装済みカタログと読み込める複合施設店舗名を生成します。外部サービスの429制限や容量不足時には失敗分だけ残り、再操作で再試行できます。中止ボタンを用意しています。
- 保存済みの部品がすべて揃う場合は通信なしで組み立て再生します。部品が欠けている場合は、案内途中で長時間待たせないため従来の全文音声保存／生成へ切り替えます。再生不可なら端末音声に戻します。
- カメラが車両を検知しても本人が駐車完了を確定するまでは「駐車完了」と断定しません。
- 追加台本のうち、入口通過・自動経路・駐車時間・退出検知など未実装の判定機能に紐づくものは定義のみで、発話を捏造しません。
- 外部音声の文章送信は、利用者が音声ファイル方式を**明示的にオンにして事前保存／再生する場合のみ**実施します。日本語以外は従来の端末音声のままです。
- 保存容量の上限は750個の音声部品です。ストレージ削除・ブラウザーの自動再生制限には依存します。

### 事前生成した音声の保存と再生（2026-10-29）

利用者アプリの音声設定で、日本語の「音声ファイル方式を試す」を有効にすると、保存済みVOICEVOX音声を優先して再生します。
未保存の場合だけ tts.quest に日本語の案内文を送信して生成し、成功した音声をその端末の Cache Storage に保存します。利用者の同意なしに外部へ案内文を送信しません。

- **停車中**に対象施設を選び、音声詳細設定の「選択施設の案内文・駐車枠を事前保存」を押すと、固定文と選択施設の名前・登録された区画番号を音声部品として保存します。区画を案内する際は**1件だけを2回**読み上げます。
- 発話内容は、音声用読み仮名の正規化後の**文章全体**をキーに照合します。空き数や営業時間などが変化して文章が変わった場合、未保存の新しい文章として生成することがあります。
- 保存済み音声は通信なしで利用できます。端末がCache Storageを削除した場合やブラウザーを変更した場合は、再度事前保存が必要です。最大750ファイルを保存し、古いものから削除します。
- 外部サービス接続が失敗した場合や未保存のままオフラインになった場合は、既存の端末音声へ切り替えます（端末音声の対応状況と自動再生可否はブラウザー依存）。
- 非日本語は従来どおり言語別の端末音声を利用します。外部音声の利用設定は初期状態でオフです。
- クラウド側のSupabaseテーブルや管理者アプリの変更は不要です。
- キャッシュは閲覧端末内にのみ保存し、音声文章はキャッシュURLではなくSHA-256で識別します。音声の生成時には施設名・区画番号を含む文が第三者のサービスに送信されます。
- テスト: `node --test tests/voice-audio-cache.test.cjs`。生成済み音声の再利用、オフライン再生、重複の事前生成防止をモック通信で検証します。

## 店舗の満・混・空と空きなし案内

施設一覧と検索結果は同じレイアウト状態から判定します。保存データとデモを区別して表示し、実際のリアルタイム空き情報ではないことを画面上部に表示します。

| 表示 | 研究用の判定 |
| --- | --- |
| 満 | 利用可能な区画があり、その全区画が使用中 |
| 混 | 空きが1～3区画、または利用可能区画の20％以下 |
| 空 | 上記より空きが多い |
| — | 登録区画ゼロ、未確認・不明な状態の区画がある |

`unavailable` は利用可能な総数から除外します。状態未登録や未知の値は空き扱いせず、案内対象にも含めません。未登録施設では既存の12区画デモを使用しますが、登録済みの空レイアウトをデモに置き換えません。

空きが少ない場合は残り区画数を表示・読み上げます。希望車種に一致する空きがない場合も通過案内を表示し、他車種に空きがある場合は満車と断定しません。空きなし画面には「公道で順番待ちをせず、周囲の安全を確認してそのまま通過してください」と表示し、音声案内、施設変更、再検索を用意します。音声オフの場合は自動発話せず、音声ボタンで任意に再生できます。

音声の詳細設定・接続説明は折りたたみ、主画面では施設名・状態・操作を優先します。外部音声の送信説明はオンにするチェックボックスの直下に残しています。
